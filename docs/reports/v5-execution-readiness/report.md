# 墨衡 V5：BTC 执行就绪度诊断

生成日期：2026-08-22（北京时间）
结论等级：研究开发证据；不可晋级、不可累计 Shadow 天数、不可触发订单

## 决策摘要

V5 把同一组因果预测拆成两个互不混淆的现金账本：7 资产研究组合，以及当前唯一执行白名单 `BTC-USDT`。组合在 24 bps 往返成本下为 `+12.0056%`，但这个数字不能代表当前执行器；BTC-only 切片为 `+0.9311%`，48 bps 压力成本下仍为 `+0.2309%`，最大回撤 `0.6577%`。

BTC 切片唯一失败门是交易样本：840 天只有 10 笔闭环，低于预声明的 20 笔。它是值得进入下一阶段的正向候选，但不是可上线实盘的证据。最快可信路径是冻结候选和成交协议、开始真正的前瞻 Shadow，再用 Demo 成交验证滑点/费用/残余；跳过这些步骤会把“快”变成不可估计的实际资金风险。

## 第一性原理目标

系统真正要最大化的不是历史收益率，而是在可生存风险约束下、可重复执行的未来净期望：

`可实现净期望 = 信号边际 - 手续费 - 滑点 - 容量/成交偏差 - 模型漂移 - 运行故障损失`

因此每个“收益提升”必须回答五个问题：预测发生时信息是否已经可见、订单能否按同样价格语义成交、成本是否足够保守、盈利是否依赖少数资产/时期、失败时是否会停止新风险。V5 优先修复证据与执行白名单不一致，而不是继续堆叠模型复杂度。

## 发现与归因

1. **组合收益不是 BTC 执行收益。** XRP-USDT 历史净 PnL 为 `879.19 USDT`，DOGE-USDT 为 `418.23 USDT`；BTC-USDT 只有 `60.53 USDT`。组合数字不能用于批准 BTC-only 执行。
2. **收益存在时间集中。** 盈利最高的两个 30 天 episode 合计约占最终净 PnL 的 84.1%。这增加了对市场制度变化的敏感性。
3. **BTC 的成本压力方向正确。** 从 24 bps 提高到 48 bps 后仍保持正值，说明本次候选不是仅靠低成本假设转正。
4. **统计把握不足。** 10 笔交易无法可靠估计尾部风险、胜率稳定性或不同市场制度下的表现，故门槛保持失败关闭。
5. **原 Shadow 口径与执行不一致。** 旧逻辑使用信号收盘价入场和末根收盘价退出。Shadow v2 已改为确认收盘后下一根开盘入场、12 根持有、再下一根开盘时间退出，并把双边成本按成交价乘法结算。

## 本轮工程改动

- `moheng.shadow.next-open-bracket.v2`：绑定 artifact、协议版本、策略 SHA-256 和成本；策略不一致拒绝结算。
- 旧 Shadow 记录保留审计痕迹但不再计入晋级；数据库 schema 从 v2 原位迁移到 v3。
- 同根同时触发止损/止盈时先按止损，避免 OHLC 内部路径未知带来的乐观结算。
- V5 报告增加 BTC-only 独立账本、压力成本、交易数、回撤及失败原因；研究监控器先校验内容哈希和安全契约再展示。
- Supervisor 增加只读 Live readiness：90 天/100 笔前瞻 Shadow、30 笔 Demo、两侧正净结果、最大回撤不高于 3%；部署阻塞 `live_ai_execution_disabled` 始终独立显示。
- 训练页把“多币组合历史收益”和“BTC 可执行切片”并排展示；模型页显示从 Champion 到 Live 的证据轨道。

## 最短可信上线序列

1. 将 V5 的 BTC 研究候选转成安全、可审计且不反序列化任意代码的推理 artifact；冻结特征、阈值和策略哈希。
2. 用 Shadow v2 从冻结时点开始收集新数据。历史回放不能折算成任何 Shadow 天数。
3. 达到 90 天/100 BUY 且净收益为正、回撤不高于 3% 后，才允许进入小额 OKX Demo；先验证 30 个真实 Demo 闭环。
4. Demo 通过后仍只形成 Live canary 设计输入。当前代码没有 Live AI 自动执行能力，也没有获得开启权限。

当前研发优先级是第 1 步：安全执行适配器和前瞻研究 Shadow，而不是扩大实盘品种或资金。
